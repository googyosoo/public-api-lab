🔐 API 키 관리 수칙

READ FIRST

API 키는 집 열쇠이자 신용카드입니다. 유출되면 남이 내 이름·내 요금으로 API를 쓰게 됩니다. 특히 종량제 키(GPT·클로드 등)는 하룻밤 사이 수십만 원 과금 사례가 실제로 있습니다. 붙이기 전에 아래만은 지켜주세요.

이렇게 하세요

  • 키는 .env 파일에 두고 코드에서는 변수로만 불러오기
  • .env를 .gitignore에 등록하고 나서 깃허브에 올리기 — 순서가 반대면 이미 늦습니다
  • 공유용으로는 값 없는 .env.example(키 이름만) 만들기
  • 발급 콘솔에서 도메인·IP 제한 걸기 (카카오·구글맵은 필수 설정)
  • 사용량 한도·알림 설정하기 — 종량제 키의 안전벨트
  • 프로젝트 끝난 키는 비활성화·삭제하기

절대 하지 마세요

  • 코드 안에 키를 그대로 붙여넣기(하드코딩)
  • 비밀 키(sk-…, 시크릿)를 프론트엔드에 노출 — 브라우저 개발자도구로 누구나 볼 수 있습니다
  • 키가 든 코드를 공개 깃허브·블로그·단톡방에 공유 — 봇이 몇 분 만에 수집해 갑니다
  • AI 채팅창에 실제 키를 붙여넣고 질문하기 — 예시 키(sk-xxxx)로 바꿔서 물어보세요
  • 하나의 키를 여러 프로젝트에 돌려쓰기 — 유출 시 전부 뚫립니다

💡 키에도 등급이 있습니다 — 어디까지 노출해도 되나

공개 가능브라우저에서 쓰라고 만든 키 — 카카오맵 JavaScript 키, Firebase config, Supabase anon 키, 토스 클라이언트 키. 단, 도메인 제한·보안규칙 설정이 전제입니다. 설정 없이 공개하면 이것도 위험해요.
서버 전용돈이 나가거나 발송이 일어나는 키 — GPT·클로드·제미나이 API 키, 솔라피 시크릿, 토스 시크릿 키, 서비스계정 키. 반드시 서버(백엔드·서버리스 함수)를 거쳐 호출하고, 프론트 코드에는 절대 넣지 않습니다.
🚨 이미 유출됐다면? 숨기거나 지우는 걸로는 해결되지 않습니다(깃 기록에 남음). ① 콘솔에서 즉시 키 재발급(기존 키 폐기) → ② 사용량 내역에서 이상 호출 확인 → ③ 새 키는 .env로 관리 시작. 순서는 항상 "폐기가 먼저"입니다.
📌 아래 표시 읽는 법
💸 사용량만큼 과금 쓴 만큼 매달 청구됩니다. 한도 설정 없이 방치하면 위험해요.
⚠️ 무료 한도 초과 시 과금 개인 프로젝트 수준이면 대개 무료 범위 안이지만, 공개 배포하면 넘길 수 있습니다.
표시가 없는 API는 완전 무료이거나 호출 한도를 넘으면 그냥 차단됩니다.
